# 高级质感、液态课表与秒级时间：设计调查

日期：2026-09-23。范围：用户意见记录、官方资料调查、现有代码核查与下一版设计建议。未修改 App，未生成图片，未进行竞品登录体验或浏览器性能测试。

## 1. 建议采用的整体方向

建议以 Things 的内容展开方式、Linear 的视觉层级、Morgen 的拖动排程为参考，结合思源宋体，形成安静、有秩序的学习工作台。让玻璃高光、浮起和回落出现在悬停、拖动、展开这些关键动作中。

“像付费软件”是审美目标，不等于价格或市场排名。以下区分官方已描述的行为和本项目的设计推断；具体尺寸、颜色、动画时长均为待验证建议。

|参考|官方资料中可核实的做法|留白可借鉴的部分|
|---|---|---|
|[Things](https://culturedcode.com/things/features/)|打开任务时平滑展开；附加字段按需出现；拖动用于调整安排。该页面回顾 Things 3.0 设计，不当作最新版本完整评测。|正文像整洁的纸面，任务从原位置展开，减少常驻按钮。|
|[Linear，2026-03-12](https://linear.app/now/behind-the-latest-design-refresh)|统一页头与操作位置、减弱侧栏、减少多余图标和背景、调整为低饱和暖灰。|用对齐、层次和稳定的位置形成精致感；字号仍遵循本项目大字要求，不照搬其紧凑密度。|
|[Morgen](https://www.morgen.so/guides/manually-time-block-in-morgen)|任务拖入日历，拖动底边改变时长；可为同一任务安排多个时段。|待排任务与课表同屏，位置和高度直接表达开始时间、占用时长。|
|[Fantastical](https://flexibits.com/fantastical/help/calendar-views)|完整日历提供日、周等视图，侧栏配合事件概览；支持键盘使用。|课表提供“今天 / 本周”切换，沿用同一套时间轴。|
|[Apple Liquid Glass](https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/)|材质会响应环境和移动；控件与导航构成位于内容之上的功能层。|把玻璃集中在活动任务、浮层和少量控制器，正文保持清楚。|

## 2. 图标怎样更直观、更精致

优先比较 Phosphor 的 Regular 与 Duotone（双色层次）作为统一图标家族；它官方提供六种字重/样式。下一步原型应把相同语义的图标并列比较，再决定是否替换现有 SVG。来源：[Phosphor 官方项目](https://github.com/phosphor-icons/web)。

建议导航和动作使用简洁轮廓，任务类别使用少量双色填充；不混搭多套轮廓、表情和立体贴图。建议图标约 20–24px，在相同容器内做视觉居中；这些是本项目参数。

|用途|建议语义|必要文字|
|---|---|---|
|主控制台|带今日标记的日历|今天|
|课表|带明确行列的日历网格|课表|
|投入统计|柱状图|统计|
|课程任务|书本或黑板|课程名|
|论文阅读|带文字行的文档|论文/任务标题|
|实验任务|烧瓶|实验标题|
|竞赛|奖杯|竞赛名|
|开始、暂停、完成|播放、暂停、勾选|相应动作名称|

图标只辅助识别。不能让同一个星芒同时代表智能、重要、科研、开始，也不能把“任务统计”画成容易理解为健康监测的心电图。对于数学、英语等难以仅凭图形区分的课程，保留课程简称和标题。

质感由三件事配合：统一笔画与比例、节制的类别颜色、操作状态的连续变化。主体建议暖白/石墨灰、深色文字、一个主强调色；类别颜色只占细边或小色块。继续中文思源宋体、英文和数字 Apple 平台系统字体，正文以 18px 为起点。英文数字使用等宽数字特性，让秒数变化时列宽不跳。

## 3. 主控制台与课表布局

顶部：日期、今天/本周切换、添加任务。下一行：今日任务完成、今日已记录投入、预计剩余、今日可用时间。统计标签必须区分投入、估计和空闲。

主体：课表为主要视觉区域，旁边为待排任务、当前专注和一句可操作分析。避免在顶部和侧栏重复同一组统计。窄屏切到单日，任务详情用底部面板呈现，文字不为塞进七列而缩小。

- 纵轴逐小时标 `08:00`、`09:00`、`10:00`；半小时用更轻的线。分钟精度通过任务位置和编辑器实现，不铺满每分钟文字。
- 单日模式保留足够任务宽度；周模式横轴显示日期，今天有轻微列背景。
- 默认可从 08:00 开始；若有更早或更晚的事件，扩展可见时段，不能隐藏真实日程。
- 时间位置严格按比例：`top = (开始分钟 − 网格起点分钟) × 每分钟像素`，高度按时长计算。
- 建议原型以 120px/小时起步，并可调整密度。此时一分钟为 2px，仍需时间输入和键盘微调，不能只靠鼠标。
- 短任务若放不下标题，保留真实时长细条，配合临近标签或详情列表；不要偷偷把 2 分钟任务画成 20 分钟，也不要让放大的点击区域遮住旁边任务。
- 同时发生的任务并列，固定课程与可移动任务有清楚区别；当前时间线随时间更新但不抢眼。

## 4. 悬停液态玻璃：可实施的交互规格

以下为方案建议，未完成浏览器验证。

|状态|视觉与内容|操作|
|---|---|---|
|静止|稳定浅底、类别细边；标题与起止时间常驻|一眼看懂做什么、什么时候做|
|悬停 / 键盘聚焦|任务表面转换为轻玻璃，边缘高光增强；文字保持清晰|短暂停留后出现邻近详情面板|
|详情出现|显示完整标题、任务内容/完成标准、起止时间、预计剩余与已记录投入|点击固定详情，再执行开始、编辑等动作|
|拖动中|任务玻璃层跟随指针；原位置留轻轮廓，目标位置有精确时间提示|按 1 分钟吸附，移动不改变时长；关闭悬停预览以免挡住落点|
|拖动底边|上下边界清晰，起止时间与时长同步变化|调整时长，键盘和表单同样可改|
|合法落下|短促回落到最终位置|保存成功后稳定，支持撤销|
|冲突 / 保存失败|冲突边框加原因文字；保持或恢复原安排|不静默挪动其他任务|

关键细节：

1. 任务块的时间边界不因悬停放大而改变，避免用户误读时长。浮起由阴影、高光、层级实现；详情在独立浮层展开。
2. 建议悬停延迟约 250ms、材质转场 160–220ms、展开/回落 220–300ms；这些只是初始调参值。移动中的任务直接跟手，不能每次移动都慢悠悠补间。
3. 指针可移入详情继续阅读；可按 Esc 关闭；不会读到一半定时消失。键盘聚焦和点击提供等效入口。遵循 [W3C 悬停与聚焦内容原则](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)。
4. 触屏通过点击打开详情，拖动使用明确把手或长按进入，保留正常滚动。减少动态效果时保留边框/透明度反馈，取消位移弹性。
5. 标题、时间、冲突等核心信息不隐藏到悬停中，固定课程明确提示不可随意拖动。

Web 实现可以组合半透明底、`backdrop-filter`、边缘渐变、高光和阴影。[MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter) 说明该属性处理元素背后的像素，需要透明或半透明表面才能看到效果。它本身不等于 Apple 的完整实时折射材质；当前项目应称“Liquid Glass 风格”。只有在初版阅读性、拖动性能达标后，再单独评估局部折射增强。不要把整张课表截图变形，也不要让正文文字跟着扭曲。

## 5. 秒级统计与分钟级排程

|数据|建议显示|口径|
|---|---|---|
|本次专注|`00:23:47`|暂停不增长，恢复后继续累计|
|今日已记录投入|`01:32:18`|只累计归属于今天的实际记录；计时和补记来源需要可辨识|
|预计剩余投入|`约 01:10:00`|可保留秒值，但“约”说明它仍是估计|
|距下一项开始|`00:12:36`|随当前时间变化，过时后改为进行中/已开始|
|今日可用时间|`02:08:24`|从现在到可用时段末尾的空闲区间，扣除占用和适用限制；不能简单用午夜减现在|
|课表起止时间|`08:37–09:22`|分钟级定位与输入，不显示无意义的秒标签|
|任务数量 / 比例|`2 / 4`、`50%`|保持本来的单位|

计算层保存整数秒，最后一步才做格式化。估算源只有分钟时，补成 `:00` 不会使估算变得更准确。对未知值显示“未估计”，不能显示零。

时间推进根据开始时间、暂停区间与当前时间重新计算；每秒刷新只是渲染频率，不能靠每次定时回调机械 `+1`。恢复前台应立即校准。跨日累计须按每天边界分割，并防止已结束记录与运行计时重复计入。秒字段只更新对应文本节点，避免整张课表每秒重绘；秒数可稳定切换，不做持续翻牌。

“专注时长”与“含补记的投入”是否分开，需要记录来源支撑。当前模型的来源区分不足，不把全部历史补记包装为精确专注计时。主界面可以短标签呈现，完整统计定义放详情。

## 6. GPT Image 是否有必要

结论：核心界面无需依赖图像生成；它可以在布局定型后，辅助少量品牌资源。

|资源|建议|
|---|---|
|App 图标方向、品牌主视觉|可生成候选，选定后做小尺寸识别和主题适配检查|
|空状态插画、欢迎页插画|可选；保持数量少、风格统一|
|玻璃材质气氛图|可作探索参考，真实交互仍由代码完成|
|导航图标、任务类别图标|优先统一矢量图标体系，必要时人工微调|
|课表网格、时间数字、按钮和正文|用真实组件与文字实现|
|实时玻璃、拖动和悬停状态|用代码实现，图片不能替代交互|

官方图像生成文档列出的限制包括精确文字位置与清晰度、多次生成的一致性，以及结构敏感布局的精确控制。因此这里把它定位为资源与视觉方向工具。透明背景能力应以具体模型支持为准，不能把生成的玻璃图片当作真正的背景折射。[OpenAI Image generation](https://developers.openai.com/api/docs/guides/image-generation)

建议下一版先完成课表交互样件和图标比较，再判断品牌插画是否真的补足视觉识别。本轮没有调用图像生成。

## 7. 当前代码核查与接入顺序

已直接核查当前文件：

- `planner/domain.py` 的 `GRID = 900`，底层网格为 15 分钟；已有 `active_seconds`、`remaining_seconds` 等秒字段。
- `planner/scheduler.py` 按 GRID 切槽、检查锁定、计算缓冲及覆盖；还存在槽数量与最小块规则。不能只把常量从 900 改成 60，否则原“4 槽”的一小时片段可能变成四分钟。
- `planner/static/day.js` 拖动吸附、默认时长和表单仍含 900000ms、15 分钟及 `step=900`；当前拖动比例为 64px/小时。
- `planner/static/app.js` 的 `duration()` 会向上取整分钟或转为一位小数小时；周日历使用 15 分钟档位的位置类。计时显示已包含秒，但不能据此声称所有统计已支持精确显示。

下一步建议顺序：

1. 做一个可操作的课表样件：大字、统一图标、小时网格、悬停玻璃详情、拖动和分钟编辑。用长标题、2/5/17/45 分钟任务、并发日程检验布局。
2. 将排程分辨率与自动排程的期望时长拆开定义；手动预约可到分钟，自动排程尊重这些预约，不生成大量一分钟碎片。同步处理锁定、冲突、缓冲与旧数据。
3. 统一秒级格式、运行计时与今日统计归属；明确估算/实际/空闲。
4. 接入主控制台，验收键盘、触屏、撤销、刷新恢复、跨日和失焦计时，再微调玻璃强度和动画。

完成标准：能把任务安排为 `08:37–09:22` 并刷新保持；累计 `59` 秒到 `60` 秒不丢失；暂停后不增长；悬停不挤动时间线；详情可移入、可关闭；短任务与长中文标题可读；200% 文字缩放及窄屏能完成同样操作。

以上是研究与待验证设计，不代表已接入、已测性能或已完成可访问性验收。
