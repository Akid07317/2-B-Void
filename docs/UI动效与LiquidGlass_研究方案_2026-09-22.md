# 留白：组件动效与 Liquid Glass 研究方案

核验日期：2026-09-22。对象是当前原生 HTML/CSS/JavaScript 前端，以及已经确定的“清单导航＋任务列表＋当天日历”方向。本文件是组件清单、技术研究和实施方案；没有把候选动效记为正式功能。

## 结论与范围

推荐先建设统一的状态切换和动画机制，再把玻璃材质集中用于浮动导航、日期工具栏、短菜单和专注浮条。任务正文、日历时间网格、课程块、表单正文保持稳定底色。视觉目标是清晰的工作界面和有连续性的操作。

动画、玻璃材质、业务状态是三个不同层次：任务可以有流畅动画而完全不透明；玻璃可以静止；动画完成也不能被用作数据已经保存的依据。

当前正式前端有按钮约 150 ms 的背景/阴影/位移过渡、任务卡片悬停过渡、弹窗背景 5 px 模糊、手机导航 15 px 模糊和 `prefers-reduced-motion` 规则。没有完整的页面、列表、拖放和形变动画系统。代码核验位置：`planner/static/style.css`、`planner/static/app.js`、`planner/static/index.html`。

新日计划方案的拖动、调整时长、快速录入、勾选和撤销属于独立设计预览；正式前端仍有旧总览和完成表单。不能把两者的完成程度合并。产品方向以 `docs/日计划交互重设计.md` 为准，不再为将取消的英雄卡片设计新动效。

## Liquid Glass 需要拆解的部分

Apple 将光学和运动作为同一个材质系统设计，并将其用于浮在内容上方的导航和控件；这些是官方设计意图，不是本项目已经实现的行为。[Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)

| 部分 | 用户看到什么 | Web 近似办法 | 要防止的问题 |
|---|---|---|---|
| 半透明底色 | 看得见背景的大致色彩 | 带透明度的背景填充 | 不用父元素整体 opacity 把文字一起变淡 |
| 散射 / 磨砂 | 背景细节被柔化 | `backdrop-filter: blur(...)`，必要时轻调饱和度 | 模糊太强就只剩毛玻璃，太弱又使文字相互干扰 |
| 边缘折射 | 边缘下的线条弯曲、压缩或拉伸 | 由轮廓计算位移场，对背景纹理重新采样 | 不能拿随机噪声扭曲整个区域，也不能扭曲控件自身文字 |
| 边缘高光 | 边界有方向性的亮暗变化 | 薄边缘渐变；更高阶用轮廓法线计算亮度 | 均匀粗白框、持续扫光会显得像塑料或广告 |
| 厚度与阴影 | 浮在内容之上，扩大后更厚实 | 外阴影、极弱内侧暗边、展开时调整遮蔽 | 大范围发光和重阴影破坏轻盈感 |
| 按压弹性 | 按下变薄或微变形，松手恢复 | 小幅 scale 或可控轮廓；接收最新输入的弹簧 | 不用每次从头重播的固定长动画 |
| 连续形变 | 一个按钮展开成一块菜单或计时条 | 同一轮廓容器插值大小和圆角；文字独立布局 | 直接放大整张位图会拉伸文字和圆角 |
| 相邻融合 | 同组控件靠近时轮廓接合 | 原生容器；Web 高阶可用平滑合并的距离场 | 不把普通缩放宣称为真正融合；不在密集控件中滥用 |
| 背景与偏好适配 | 换背景后文字仍清楚，减少动效时更安静 | 保守底色、主题令牌、手动实色模式、能力降级 | 单靠混合模式不能保证文字对比度 |

Apple 的 `regular` 更适合通用控件；`clear` 用于视觉内容丰富的背景。我们的正文密度较高，第一版借鉴 regular 的清晰度和厚度，不以高透明为目标。[Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

## 折射究竟怎样实现

普通半透明是颜色混合；磨砂在混合前让背景变模糊；折射还要改变“从背景哪个位置取像素”。控件上的文字、图标最后单独绘制，因此不会随背景一起扭曲。

可执行的近似过程：

1. 获得需要处理的背景图像 B。对于 CSS backdrop，浏览器负责背景采样；对于 Canvas / WebGL，应用必须自己提供图像或渲染纹理。
2. 用圆角矩形的轮廓求每个像素距离边界的距离 d，以及朝外的单位方向 n。
3. 只在一条边缘带内给出位移幅度 a(d)，中心接近 0；得到位移向量 D = a(d) × n。
4. 在输出位置 p 读取 B(p + D(p))；需要时加入轻模糊、底色、高光与阴影。
5. 在最上层放清晰的前景文字与真实交互控件。

这里的 a(d) 可以先用平滑函数调出视觉效果，再研究更接近物理的厚度曲线和折射。它不是 Apple 私有实现，也不等同完整的光线追踪。没有必要为了小工具栏把整个 App 改成三维场景。

SVG 路线可以用 R / G 通道表达水平 / 垂直位移，交给 `feDisplacementMap`。MDN 的定义是：

```text
P'(x,y) = P(x + scale × (R(x,y) - 0.5),
             y + scale × (G(x,y) - 0.5))
```

所以通道范围 0 到 1 对应约 −scale/2 到 +scale/2。要表达最大 ±A 的位移，需要匹配 `scale = 2A`；不能误写成 `scale = A`。若用 RGB 位移图，需明确 `color-interpolation-filters="sRGB"`，避免中性通道被默认 linearRGB 转换后产生整体漂移。[MDN feDisplacementMap](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feDisplacementMap)

Kube 的作者实验提供了从折射近似到 CSS/SVG 的完整探索，但作者明确限定了场景和浏览器，不能当作苹果源码或全平台支持证明。本文按 MDN 的定义核对位移尺度。[作者实验与限制](https://kube.io/blog/liquid-glass-css-svg/)

## 四条实现路线

| 路线 | 能做到的事情 | 关键限制 | 本项目选择 |
|---|---|---|---|
| CSS 半透明＋blur＋边缘高光＋动画 | 稳定的轻玻璃外观、按压、菜单展开、导航滑动 | 没有真正的背景几何折射 | 正式 Web 第一阶段基础 |
| CSS backdrop 引用 SVG 位移滤镜 | 对真实页面背景产生几何位移，适合小胶囊和工具栏 | SVG 能渲染，不代表能作为 backdrop 在每个浏览器正确工作 | 第二阶段可选增强，先做浏览器画面实测 |
| Canvas / WebGL 自绘材质 | 自由控制折射、轮廓、融合、光照 | 必须有可采样背景纹理；普通 DOM 不会自动成为纹理，还要同步滚动、字体、输入与可访问性 | 研究实验或受控视觉区域，不建议重写整个任务界面 |
| Apple 原生 SwiftUI / UIKit / AppKit | 使用系统 Liquid Glass 的材质、交互和偏好适配 | 属于原生客户端工程；网页套一个壳不自动获得控件效果 | 若未来做原生客户端，优先系统组件 |

`backdrop-filter` 的普通 blur 已有广泛的现代浏览器支持，但“支持 backdrop-filter”“支持 SVG filter”和“支持 backdrop-filter:url(...) 并正确渲染”是三件事。公开实现报告仍提示组合能力存在差异。本轮未做 Safari / Firefox / Chromium 三引擎的真实 backdrop 对照，不在此给出通过承诺。[MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter)、[MDN 兼容数据问题记录](https://github.com/mdn/browser-compat-data/issues/24110)

`CSS.supports(...)` 可作为初筛，不能替代复杂组合效果的像素与交互验证。不采用固定“Chrome 可用、其他永久不可用”的规则；正式发布以实测版本记录为准。[CSS.supports](https://developer.mozilla.org/en-US/docs/Web/API/CSS/supports_static)

WebGL 需要明确上传或绘制纹理；给 DOM 上方加一块透明 Canvas，并不会获得下面 DOM 的像素。本研究对这一点的实现判断依据是纹理输入机制，后续若选择 WebGL 必须先解决背景来源。[WebGL 纹理教程](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/Tutorial/Using_textures_in_WebGL)

原生路线的核心 API：标准组件优先；自定义材质使用 `glassEffect`；交互响应使用 `interactive`；关联形变使用 `GlassEffectContainer` 和 `glassEffectID`。不要把原生 API 的能力写成当前浏览器版已有功能。[Apple 自定义 Liquid Glass](https://developer.apple.com/documentation/SwiftUI/Applying-Liquid-Glass-to-custom-views)

## 正式前端需要先整理的结构

### 1. 稳定的元素身份

当前 `render()` 会按视图替换 `#content`，筛选也会重新生成内容。列表重排和元素连续形变需要稳定的 `task-id` / `block-id`，并保存来源、目的位置。优先采用按 ID 更新节点；动画化更新时恢复焦点、选区和滚动位置。

普通日历切换可评估 View Transition API 的快照过渡，但仍须验证可中断行为和浏览器差异。它不能自动把整个页面变成 Apple 原生形变，也不适合给每次 pointermove 建立快照。[MDN View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API)

### 2. 计时器只更新数字

当前 `renderTimer()` 每秒替换整段 `innerHTML`，其中包括暂停和结束按钮。改成保留计时条、文字和按钮节点，只更新必要文本/属性；否则玻璃层、焦点和正在播放的动画可能被反复销毁。

### 3. 动画控制与业务状态分开

为组件定义状态：idle、hover、pressed、dragging、pending、success、error、disabled。hover / pressed 仅是表现；pending 表示请求未完成；success 只能来自业务成功结果。

每个可动元素最多一条同类位置动画。接到新目标时从当前显示位置继续；保留位置和速度才能形成真正连续的弹簧。WAAPI 的 cancel / reverse 提供控制能力，但简单 cancel 会清掉动画效果，必须先保存当前表现或重新设定基底状态。[MDN Web Animations API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API/Using_the_Web_Animations_API)

拖放可先给即时视觉预览，同时做本地冲突检查；最终结果仍以服务端为准。失败要有原状态快照可以回退。拖放、调整时长和撤销在正式后端尚需完整实现；动画实验不替代这些业务验收。

### 4. 材质层与文字层分离

建议封装 `GlassSurface`，只负责轮廓、背景处理、高光、边缘与阴影，标签和按钮放上层。第一版角色只分 toolbar、popover、focus-bar，明确相同角色的透明度和形变规则。

不要通过给父层整体设置 opacity 实现“玻璃透明”。父级 opacity、filter、mask 等可能建立 backdrop root，改变子元素可以采样到的背景范围。淡出浮层或裁切轮廓时必须实测这一关系，避免动画中突然失去玻璃背景。[MDN backdrop root](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter#backdrop_root)

## 初始动效参数：项目试验值

这些是拟定的调试起点，不是 Apple 官方参数，也不是已测量的最优值。

| 动作 | 起点 | 约束 |
|---|---|---|
| 悬停 / 按压 | 80–140 ms；按压缩放约 0.98 | 原生键盘焦点明显；disabled 不响应 |
| 图标 / 状态 / 小浮层 | 160–220 ms | 状态立即更新；动画不延迟业务请求 |
| 分段指示器 / 列表重排 | 180–280 ms | 连续点击追随最新目标；过滤大量行时不逐行长延迟 |
| 详情 / 面板 | 220–340 ms | 来源关系清楚，关闭可中断，文字不缩放变形 |
| 玻璃轮廓形变 | 280–420 ms 的观感目标 | 采用高阻尼、小过冲；弹簧实际时长随初速度变化 |
| 拖动 | 不为跟手位置加补间 | 松手后 100–180 ms 对齐；目标时间始终可读 |
| 磨砂强度 | 工具栏先试 12–20 px | 不在持续滚动时逐帧大幅改 blur |
| 边缘折射 | 从几像素起调，只作用于窄边缘带 | 高强度仅用于比较实验；正文可读性优先 |

优先动画化 transform / opacity；对于宽高、阴影、滤镜等会影响布局或绘制的属性，先测实际开销。玻璃本身可能增加背景处理成本，不能因为用了 transform 就保证没有重绘。[web.dev 动画性能指南](https://web.dev/articles/animations-guide)

## 三个先做透的样板

1. **日期分段工具栏**：验证材质、选中底片、按压、快速连续切换、滚动边缘和小屏。内部按钮共享材质，避免玻璃叠玻璃。
2. **任务块 → 就地详情**：验证来源位置、连续轮廓、文字独立布局、关闭回源、遮挡调整、Escape 与焦点恢复。
3. **开始专注 → 计时浮条**：验证同一容器伸展、内容替换、每秒数字更新时材质不重建，以及暂停 / 恢复 / 结束状态。

三者分别验证静态材质、空间连续性、长期状态更新。通过后再推广到短菜单、手机导航与撤销条。

## 验收与实验边界

材质验证：背景从浅到深、细文字穿过控件、彩色课程块经过边缘时，前景标签仍可读；确实能观察到背景线条弯曲；前景字形不被扭曲；展开后边缘宽度和圆角稳定。

交互验证：快速连点、动画中反向、连续拖动、滚动时打开浮层、服务端失败、撤销，以及键盘/触屏均可完成主要动作。关闭后焦点回到触发项，消失的按钮不留下不可见焦点。

性能验证：用真实课程和任务数量，在桌面与手机记录帧时间和长任务。60 Hz 单帧预算约 16.7 ms，120 Hz 约 8.3 ms，这只是刷新周期，不是已达到的性能。闲置时不持续重算光学纹理；后台页面暂停动画。局部位移图在尺寸变化时重算，而不是每次计时数字变化都重建。

偏好与降级：尊重减少动态效果；支持更不透明的外观；不支持背景滤镜时用实色；折射效果不通过验证时回到普通磨砂。浏览器对 `prefers-reduced-transparency` 的支持需要单独核验，因此要有应用内实色开关。[Apple 适配指南](https://developer.apple.com/documentation/TechnologyOverviews/adopting-liquid-glass)、[MDN 减少透明度](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-transparency)

随文交互实验只使用自绘示例背景，展示半透明、模糊、边缘位移、清晰前景和可中断形变。它使用可调的视觉近似，不宣称复现 Apple 私有光学；不代表真实 DOM backdrop 折射已通过浏览器兼容或手机性能验证。实验没有接入正式日历或 SQLite。

本轮实验验证记录：

- JavaScript 语法检查通过；用 visualize 标准沙盒外壳打开并检查画面。
- 半透明模式禁用折射与散射参数；磨砂模式启用散射；折射模式启用两者。切换与参数显示均生效。
- 检查日历文字 / 网格色块背景切换、轮廓展开 / 收回、减少动效选项，以及键盘调整滑块。
- 对照边缘位移 0 px 与 30 px，截图中可见色块边界在玻璃边缘处发生几何变化；没有把亮边本身当成折射证据。
- 320 px 浏览器视口下，标准外壳内文档宽度 / scrollWidth 均为 288 px，未出现横向溢出。桌面画面已检查。
- 浏览器控制台没有页面 error 记录。未测 GPU 耗时、帧率、系统级深色模式或真实手机硬件；不报告相应通过结论。
