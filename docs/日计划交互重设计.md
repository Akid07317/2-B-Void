# 日计划交互重设计

2026-09-22。用户否定上一版的卡片工作台和说明式界面，明确选择 Sunsama / Akiflow 式的「每天挑任务、拖入时间段」。本文件修订此前《个人学期工作台_重设计建议》的前台交互方向；已确认的课表、阶段计划和生活边界继续保留。

## 方向

首页采用清单导航、任务列表、当天日历。主要动作是收集、挑选、安排、调整、完成。取消口号、英雄卡片、常驻阶段预算卡和说明式学习路线页。阶段规则保留在模板与偏好中，出现冲突时再就地提示。

参考的是产品真实操作结构，不主张当前流行程度排名：

- [Sunsama Timeboxing](https://www.sunsama.com/features/timeboxing)：任务与日历并置，拖入时间段，并考虑结束工作时间。
- [Akiflow Today Page](https://product.akiflow.com/articles/0741055-today-page)：从当天任务列表安排日历，安排后仍可在列表中追踪。

## 交互约定

- 待安排任务始终可见；拖进日历后，仍留在当天任务列表中，两处同步。
- 直接拖动时间块改开始时间，拖动底部改时长；点击打开就地详情。
- 输入任务名、回车创建；估计、所属清单、日期和时间在详情中修改。
- 完成任务用勾选；不强迫每项任务都填写验收报告。完成状态不等于自动确认实际工时或掌握程度。
- 修改提供撤销，键盘 Cmd/Ctrl+Z可恢复上一步，输入框内保留原生文本撤销。
- 固定课程保持只读；自习移动须检查课程及5分钟通勤、其他任务、07:10—20:30窗口。
- 规则提示只在必要时出现。例如词汇时间不足、发生课程冲突。正文用任务名，不写规划方法说明。
- 手机可用安排按钮和详情编辑；桌面优先支持拖放。

## 本轮范围

制作了独立的交互设计预览。使用第1教学周课表和第一阶段学习周表作为展示基线，避免在学期起点未知时伪造日期映射。三项未安排任务是交互例子，不是额外追加的学习预算。

当前预览支持周次课程变化、星期切换、清单过滤、任务录入、编辑、安排、拖动、调整时长、完成与撤销。数据为预览内状态，不接入正式SQLite数据库；跨周真实任务实例、后台阶段预算及学习资料接入属于正式应用改造，不能把本预览当作已经完成的生产功能。

## 正式App的改造顺序

1. 用新的任务列表与日历替换总览，接回已有真实任务、课程、日志与版本机制。
2. 增加手动安排、移动、调整时长的持久化操作，服务端独立校验冲突；确认实例与循环模板的修改范围。
3. 接入按教学周展开的课表、每日时间边界和实际执行反馈。
4. 把阶段切换做成后台模板替换；AI仅在录入、拆分或用户请求重排时介入。

正式版本的关键验收是「拖完立即保存、刷新不丢、列表与日历一致、撤销可靠、冲突不静默覆盖」。视觉完成和业务完成应分别验收。

## 本轮交互验证

- 独立浏览器预览：将45分钟待办拖入13:30，再移动到14:30；拖底边拉长为60分钟，列表和日历同步。
- 拖入马原课程时被阻止；编辑为20:00开始、持续60分钟时被20:30边界阻止；改到13:30可保存。
- 嵌入预览：修改并保存、勾选完成、点击撤销均生效。
- 独立预览：输入任务名、回车进入收集箱，Cmd+Z撤销录入生效。
- 390像素预览：文档宽度和滚动宽度均为390，无页面横向溢出。
- 测试数据仅留在临时预览状态；正式应用及数据库未修改。直接页面测试外壳的初始状态格式问题已修正；不把临时外壳和正式应用混为同一实现。
