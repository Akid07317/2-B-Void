# 留白：动画、组件、人机交互与 UI 质感 · 第二轮调查

调查日期：2026-09-22。依据公开的一手设计说明、作者实验和技术文档；这是适合本项目的参考选集，不是市场占有率或“全行业最好”的排名。2026 年的更新与较早但仍有参考价值的材料分别标注。外部示例本轮以文档、图示和视频讲稿核验，没有将每个产品都做一遍实机体验。

## 先保留什么

已在本地保存 components-v1 历史检查点，包括样板源文件、独立打开版、玻璃实验、三份阶段文档和哈希清单；该备份不纳入公开仓库。可运行的当前设计实验见 [A/B 交互样板](../design/motion-study/README.md)。中文思源宋体、英文及数字 Apple 系统字体继续作为当前基线。

正式日计划仍采用清单导航、任务列表和当天日历，依据 [日计划交互重设计](日计划交互重设计.md)。本轮新增研究，不更换正式界面或数据库。

## 主要判断

本项目更值得追求的是：**清晰的阅读表面、位置稳定的控件、跟得上输入的运动、操作出错后能恢复**。材质和弹性用于强化这些体验。

建议组合：安静的任务列表与日历 + 思源宋体的文字气质 + 少量玻璃浮动控件 + 克制但可连续打断的运动。这是针对留白的设计判断，不是某个设计系统的官方配方。

## 动画：优先研究的 10 种行为

下面是本项目的候选方案与验收方式，尚未在正式 App 实现。参数是起始实验值，不是 Apple、Google 或行业通用标准。

| 行为 | 在留白里怎样表现 | 最容易做坏的地方 | 验收动作 |
|---|---|---|---|
| 即时按压 | 按下就改变明暗和极小幅度大小，释放恢复 | 等点击事件或请求结束才反馈；文字明显晃动 | 按下后移出再松手，取消动作仍自然 |
| 可重定向弹簧 | 日期选择底片从当前位置追向最新日期 | 每次点击重头播，连续点击排队 | 快速点今天、明天、后天，再点回今天 |
| 有来源的展开 | 点击任务块，详情从它的位置展开；关闭回到来源 | 只给无关面板淡入，却称作共享元素 | 展开一半按 Escape，立即反向返回 |
| 稳定的列表重排 | 新增、删除、筛选时保留任务身份和相邻关系 | 全列表重播进场；当前阅读行跳出视野 | 连续完成两项，再分别撤销 |
| 拖起、跟手与落位 | 拖起稍浮起；移动不滞后；松手短吸附到目标时段 | 拖动中持续 ease，物体落后于手；整屏晃动 | 慢拖、快拖、跨边缘，均看得见准确落点 |
| 冲突回退 | 松到固定课程上时就地说明冲突，返回原位置 | 用摇晃代替原因，或先显示成功后静默回去 | 非法落点、合法落点、取消拖动分别尝试 |
| 速度感知抽屉 | 慢拖随手，快甩考虑速度，松手停在明确档位 | 只看距离；滚动正文时误关闭面板 | 内容滚动到顶后继续滑、键盘弹出、多次改变方向 |
| 容器尺寸连续变化 | 专注按钮展开成计时条；文字独立排布 | 拉伸截图导致文字、图标和圆角一起变形 | 暂停、恢复、结束连点，不出现两套重叠控件 |
| 状态位置稳定 | 保存中、成功、失败在原位置更新 | 按钮随文案变宽，旁边控件左右跳 | 网络快慢及失败时，主要点击目标位置不变 |
| 局部滚动层次 | 顶部日期条在内容经过时增加分隔与遮蔽 | 大片 blur 长期重绘；遮挡第一行 | 滚到顶、离开顶部、浅深背景都能读清楚 |

真正值得分清的是“看起来弹”和“目标变化时速度连续”。[Compose 的 spring 文档](https://developer.android.com/develop/ui/compose/animation/customize)明确讨论中断时的速度连续性；[Motion 文档](https://motion.dev/docs/animate)也区分物理弹簧与按 duration/bounce 描述的弹簧。不能只换一条带过冲的曲线就声称获得同样的交互性质。

起始节奏：按压约 80—120ms；菜单约 140—200ms；小范围重排约 180—260ms；较大容器展开约 240—360ms。重复高频的键盘动作尽量立即响应。先对比这些范围，最后由真实操作决定；不要把所有动画统一成一个时长，也不要要求用户等动画结束才能再操作。

## 组件设计：从“有这个控件”走向“这个控件好用”

| 组件 | 下一步该研究的细节 | 项目中的应用 |
|---|---|---|
| 快速录入行 | 回车创建、创建后继续输入；中文输入法选字不触发提交；默认只要求名称 | 收集箱、今日待办 |
| 课程搜索选择器 | 搜索、候选高亮、已选值和正在输入的文本分开；无结果不丢输入 | 所属课程、清单、地点 |
| 时间 / 时长选择器 | 常用选项和精确数字输入并存；改时长直接看到占用范围 | 25 / 45 / 60 分钟、自定义时长 |
| 日期分段选择 | 选中底片连续移动；日期切换保持日历刻度和滚动位置 | 今天、明天、本周 |
| 任务行 | 任务名、时长、状态有固定位置；行内按钮出现时不挤走正文 | 当天任务与收集箱 |
| 上下文操作条 | 多选后显示适用操作；退出多选后收回；不改变任务行位置 | 批量移到某天、改课程 |
| 菜单与子菜单 | 边缘避让、明确锚点、方向键、退出后焦点归位；允许斜向移动到子菜单 | 任务更多操作 |
| 就地详情 | 保留来源上下文；编辑未提交时不能悄悄丢内容；关闭方式可发现 | 时间块与任务详情 |
| 手机底部面板 | 可点击关闭，也可拖动；输入框不被软键盘挡住；正文滚动与面板拖动分工 | 手机安排、编辑任务 |
| 撤销提示 | 显示撤销的具体对象；撤销恢复数据和位置；通知不抢当前输入焦点 | 完成、删除、移动 |
| 加载占位 | 与最终内容几何接近；短请求不闪一帧骨架；内容到达不大幅跳动 | 首次加载日计划 |
| 错误与冲突 | 保留输入，指出哪个字段或时段不合适，给出下一步 | 重叠课程、越过时间边界、保存失败 |

[WAI-ARIA Combobox 模式](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)给出候选选择、Escape 和编辑键的预期行为，可作为选择器验收依据。中文输入法组合状态可通过 [KeyboardEvent.isComposing](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/isComposing)识别；仍需实际输入法验证。

一个容易忽视的好交互是“给鼠标去子菜单的路径留余地”。[Floating UI 的 safePolygon](https://floating-ui.com/docs/usehover)用动态区域判断指针是否正向浮层移动，防止途经空隙就关闭。当前样板还没有多级菜单，先把这项作为后续需要时的方案，避免提前增加复杂度。

## 人机交互：五个更值得投入的方向

### 1. 让操作对象保持连续

用户选中的是同一项任务，即使它从列表被安排到日历、打开详情、完成后进入已完成区，也应保留名字、身份和可追踪的位置。动画帮助解释变化；对象身份由数据和稳定节点保证。

### 2. 拖动与精确输入并存

桌面拖放适合直接安排；“安排到…”按钮、日期和时间输入适合精确修改、手机和辅助操作。[WCAG 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)要求适用的拖动功能提供无需拖动的单指针替代；单独增加键盘快捷键并不满足这项要求。

### 3. 允许改变主意

按压后移出可以取消；打开一半可以关闭；拖起后 Escape 返回；完成后可以撤销。将“取消、反向、失败恢复”写进组件状态，而不是动画完成后才重新接收输入。

Apple 的 [Designing Fluid Interfaces，WWDC18](https://developer.apple.com/videos/play/wwdc2018/803/)用位置和速度预测手势落点。这是较早的原理材料，本轮作为手势研究基础，不把其中的旧 API 当作最新实现指南。

### 4. 常用动作短，复杂信息按需展开

创建任务先输入名称；课程、估计时长等按需补充。详情在来源附近出现，长内容再进入侧栏或手机面板。命令面板可以服务熟练用户，但每个核心动作也应有可发现的入口。

### 5. 反馈必须对应真实状态

按下反馈可以即时给；保存成功需要真实成功；乐观更新必须明确 pending 并有失败恢复。完成任务不自动等于已经学习相同时长，更不代表掌握了知识。正式排程的冲突校验和实际执行记录仍按业务规格处理。

## UI 质感：建议研究四层，而非只调透明度

以下为本项目原创的视觉实验提案。当前已确定字体，其余仍待对照。

| 层次 | 建议实验 | 判断方法 |
|---|---|---|
| 字体与排版 | 思源宋体中文 + Apple 英文和数字；任务正文保持舒展，时间数字对齐；真实字重优先 | 同屏读 20 项任务，是否容易扫读；检查中文、英文、冒号与数字的基线 |
| 内容表面 | 微暖或中性浅底、稳定实色任务区；主要依靠间距与轻分隔组织结构 | 关闭所有动效后，依然能一眼认出任务、时间、主动作 |
| 控件体积 | 统一的圆角层级、少量接触阴影；按下时阴影和尺寸协同变化 | 不靠发光也能看出可点击；嵌套圆角是否协调 |
| 浮动材质 | 只在日期条、短菜单、计时条试轻玻璃；文字层稳定清晰 | 在密集文字和浅深色背景上测试，而非只看漂亮壁纸 |

可以比较三种气质：A 中性安静，B 微暖纸面，C 中性内容＋轻玻璃控件。“纸面”首先通过颜色与字体表达，不默认铺纹理；细噪点、镜面扫光和大面积模糊仅在能证明改善观感时才加入。

本轮不建议：每张卡片都玻璃化、所有列表逐项飞入、按钮长期发光、计时数字每秒弹跳、完成普通任务时全屏庆祝。这些是针对高频学业规划界面的取舍，不是对其他产品类型的普遍否定。

## 当前样板已经有什么，还缺什么

| 项目 | 保存版本里的事实 | 下一轮要补的证据 |
|---|---|---|
| 字体 | 本机思源宋体 Regular，按 Unicode 范围覆盖中文；英文数字走系统字体 | 正式发布的分包与回退；真实中等/较粗字重，不依赖合成加粗 |
| 按钮、开关、分段 | 已有按压、滑动、状态反馈 | 连续重定向是否保持速度；键盘高频操作是否足够快 |
| 完成与撤销 | 样例能完成、收起、恢复 | 实际列表筛选、多次操作和异步保存同时发生时的数据与焦点一致性 |
| 详情展开 | 当前是位移与淡入，独立详情框 | 从来源任务块展开的几何连续性，开到一半关闭的反向行为 |
| 菜单 | 固定定位、方向键、Escape | 窗口边缘自动避让；滚动时定位更新；移动端触控 |
| 保存和进度 | 已标示为模拟流程 | 接入正式保存、网络失败、重复请求和持久化撤销 |
| 中文输入 | 有输入框与回车保存 | 源码未显式处理 isComposing；下轮先补中文输入法选字验收 |
| 玻璃 | 轻玻璃 CSS；另有 Canvas 自绘背景实验 | 真实背景下的可读性与性能；不能把两种演示当作原生材质 |

这一表来自对保存源文件的当前检查，不把之前的测试结果扩大成正式应用验收。源码 `animate()` 先取消已有动画再播放给定帧，尚不能保证所有中断场景从当前显示位置和速度继续。

## 下一轮实验，按顺序做

1. **连续交互实验**：日期底片快速连点、任务展开后立即关闭。比较固定缓动与保持速度的弹簧。过关条件：无跳回起点、无排队、无失效点击。
2. **任务操作实验**：完成 → 相邻行重排 → 撤销；同一个任务从列表安排进日历。过关条件：身份、焦点、数据和视觉同步，失败可以恢复。
3. **手机面板实验**：慢拖、快甩、内容滚动、键盘弹出、点击关闭。过关条件：不误关、不遮输入；桌面缩窗通过不能代替真机检查。
4. **质感对照**：完全相同的内容和交互，对比中性、微暖、轻玻璃三版。过关条件：既能看出风格差异，又不降低阅读和点击准确性。

每轮用同一组 20—30 项示例任务，包含长标题、中英混排和重复操作；加上减少动效模式、窄屏、长文本与输入法。先做 5—8 人的探索性可用性观察，记录完成时间、误操作、反复寻找控件和主观疲劳；这个规模用于找问题，不用来宣称统计显著提升。

性能方面先检查拖动期间是否反复做整页布局、计时是否重建按钮、是否无条件重绘大块模糊。单个可合成属性不保证整页流畅，必须在目标设备上测量；测试设备、刷新率、浏览器和列表规模一并记录。

## 技术选择保持克制

当前原生 HTML/CSS/JS 工程继续用稳定节点、CSS transitions 和 WAAPI 做基础。真的需要连续速度、惯性和统一控制时，再评估 [Motion 的 JavaScript animate](https://motion.dev/docs/animate)；其文档当前区分物理弹簧与时长式弹簧。无需为了几个动效迁移整个框架。

复杂浮层需要边缘避让时可评估 Floating UI 的定位能力；React 的 useHover 和 Radix 是行为/架构参考，不能原样当作原生 JS 项目的即插即用依赖。玻璃研究沿用 [上一轮方案](UI动效与LiquidGlass_研究方案_2026-09-22.md)，先完成稳定底色版本，再测小面积增强。

本轮保存与调查已完成；上述四组实验是下一轮工作，尚未实施。
