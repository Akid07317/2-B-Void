# 主流 App 怎样做出高级感、简洁感与交互巧思

调查日期：2026-09-23。配套：[留白 · 30 类交互与页面入场规格草案](留白_30类交互与页面入场_规格草案_2026-09-23.md)。

## 结论与这轮的修正

精致界面的特点，是静止时容易阅读，操作时回应细腻，变化后仍能找到方向。进入页面、按下、移开、展开、取消、等待、完成、撤销，每一个过渡都参与塑造这种感觉。**动效应该在布局和交互原型阶段一起设计。**只检查静态截图，或者给所有组件统一加淡入，都会漏掉很大一部分质量。

前一轮把重点过多放在减卡片、调字体和克制装饰上。那些工作必要，但不足以解决用户提出的“操作各处都应该有高级感和巧思”。本轮把调查对象扩展到完整状态过程，同时保留不同产品的个性；不把“克制”理解成没有表现力。

资料分为三种：官方产品案例说明已经公开的设计；设计系统说明一套团队规范；文中“留白建议”是针对本项目的设计推导。没有逐一登录并实测所有 App，没有从演示视频测量动画时长，也不把旧案例写成当前版本的全部行为。共整理 **15 组产品与设计体系、28 个一手资料页面**；它们是参考选集，不是市场排名或美感的客观评分。

## 二、6 组平台与设计体系：把经验变成可复用规则

| 体系 | 已核验的重点 | 留白如何采用 |
|---|---|---|
| Apple | 手指按下就反馈；运动可被中断；弹簧可无明显回弹；Liquid Glass 将材质与交互联动 | 重点研究反向、跟手、速度连续和有来源的展开；小面积材质随状态变化 |

| IBM Carbon | 区分效率性和表达性动效；强调语义一致、连续对象及分组入场 | 给首次页面进入设计节奏；高频操作短，关键时刻可稍有表现 |
| Atlassian | 高频小交互更短；进入帮助定位，退出更快；可围绕触发点展开 | 菜单从按钮旁出现；关闭尽快让出内容；避免重复操作堆积 |
| Ant Design | 强调自然、高效、克制；退出可整组快速结束；小箭头应服务内容状态 | 中文效率工具可以细腻而不繁忙；精力集中在任务本身的变化 |

## 三、值得拆开的 8 种巧思

### 1. 入场有阅读顺序，也有结束点

Carbon 给出了从稳定界面到动态内容的编排示例，也讨论短错峰与总时长上限。它解决的是视线如何落到内容上。[依据 S22](https://carbondesignsystem.com/elements/motion/choreography/)

**留白建议：**保留已出现的导航和小时轴，让课表主体与摘要以小幅度、重叠时间进入。分三组足够，长课表不要每项任务挨个等待。首屏过程结束后应完全安静。用户开始操作时，入场立即让位。

### 2. 用户感觉自己一直拿着同一个东西

Things 的任务展开、Telegram 的输入文字变成消息，都提供了对象变化的具体案例。[Things 演示](https://culturedcode.com/things/features/)、[Telegram 历史演示](https://telegram.org/blog/animated-backgrounds)

**留白建议：**同一个任务从待安排列表进入课表，再进入详情，标题、颜色和空间来源保持可追踪。可以只让边框与容器过渡，文字保持正常排版，避免整张内容像橡皮一样拉伸。来源离开屏幕时采用就地淡变，不让元素穿越整个窗口。

### 3. 精致感经常在“我改主意了”时出现

Apple 明确讨论动画过程中继续接收操作，弹簧也可保持运动连续性。[S01](https://developer.apple.com/videos/play/wwdc2018/803/)、[S02](https://developer.apple.com/videos/play/wwdc2023/10158/)

**留白建议：**详情打开一半按 Escape 就返回；日期底片尚未到达周二，点周四便从当前位置继续；拖动时松开、再抓起仍对应当前位置。相比一次播放得很漂亮，这些中间状态更能体现完成度。

### 4. 简洁来自信息出现得合时宜

Figma 把混合模式简化成图标后，发现读状态变慢；随后重新显露必要信息。这个复盘提醒我们，隐藏也有成本。[S09](https://www.figma.com/blog/our-approach-to-designing-ui3/)

**留白建议：**任务名称、起止时间、冲突和运行状态常驻。编辑、复制、更多操作按需显露。悬停预览应在原对象附近，并给指针从任务移到浮层留出通路。触屏点击与键盘聚焦也能得到同样信息。

### 5. 运动需要编组，不能各自抢戏

Google 的历史 Photos 案例指出，多项删除如果让每个缩略图各自补位，路径容易交叉混乱；团队为整体网格设计了更清楚的变化。[S13](https://design.google/library/making-motion-meaningful)

**留白建议：**批量安排或完成任务时，一次处理整组变化；标题、计数、课表和提示组成同一段反馈。留一个主运动，其他区域用弱变化说明结果。秒级计时不参与这些进场和重排。

### 6. 材质应随着操作产生因果

Things 的 OS 26 更新明确把光泽、尺寸和拖动形变联系起来；Apple 同时讨论材质的动态与适配。[S05](https://culturedcode.com/things/blog/2025/09/things-for-os-26/)、[S03](https://developer.apple.com/videos/play/wwdc2025/219/)

**留白建议：**悬停时间块时边缘提亮、接触阴影稍增；拖起时才出现浮起感；落位后恢复。详情浮层可有玻璃，任务文字底部仍保持稳定对比。材质在“正在操作哪个对象”上发挥作用。

### 7. 个性留给有意义的节点

Slack 的团队为加入通话、处理未读等节点设计声音、文字和动画；Duolingo 的视觉也能表达教学内容本身。[S12](https://slack.design/articles/crafting-digital-delight-inside-slacks-studio-team/)、[S15](https://blog.duolingo.com/developing-math/)

**留白建议：**日常勾选只需精细的小反馈；完成本次专注后，让真实用时落入今日累计；完成当天计划时出现一次短暂的“收束”动作。情绪节奏可以是安静、投入、完成后的舒展，与中文宋体气质一致。

### 8. 没有闪烁和错位，也是设计成果

Raycast 工程复盘把打开时的绘制同步、弹层与窗口细节视为产品手感的一部分。[S07](https://www.raycast.com/blog/a-technical-deep-dive-into-the-new-raycast)

**留白建议：**提前确定数字宽度、按钮占位和浮层方向；字体到达不应让页面大幅重排；保存状态更新不挤走鼠标下的按钮。拖动期间持续读取数据、整页重建或大块模糊重绘，都需要实际性能检查。

## 四、为什么套上现代样式，仍会显得粗糙

以下是本项目的诊断框架，不是对每个现有组件已经完成的实测结论。

| 观感问题 | 常见具体原因 | 应该检查和修改的地方 |
|---|---|---|
| 像组件演示页 | 每块内容都带圆角、边框、标题、说明和同等阴影 | 减少重复框架，让日程、任务、统计有明确主次 |
| 漂亮但不顺手 | 点击后等动画结束才能再点；菜单打开时焦点迟到 | 让状态立即响应，过渡可以反转、合并或结束 |
| 界面总在晃 | 每个数字滚动，每张卡片浮起，每次导航重播 | 按操作频率分配表现力；保持时间刻度与正文稳定 |
| 简洁但难找 | 隐藏当前值、删除文字标签、主要动作只在 hover 出现 | 将关键状态放回稳定位置，隐藏低频补充动作 |
| 玻璃像塑料 | 大片统一 blur、刺眼白描边、多个透明层互相叠 | 控制使用面积、背景内容与边缘亮度；检查真实文字可读性 |
| 动画像模板 | 入场、返回、日期切换、错误全用同一种上移淡入 | 分清层级、同级变化、对象变形、撤销和反馈 |
| 时快时慢 | 时长任意；小菜单比大面板还慢；各区依次等待 | 建立少量运动规则，控制整个过程的总时长 |
| 缺少产品性格 | 只模仿颜色和圆角，没有自己的关键交互 | 围绕“安排时间、进入专注、完成一天”设计少数标志性动作 |

## 五、对留白的具体方向

采用“安静的学习台面，操作时有明确触感”的方向。维持用户已提出的中文思源宋体、英文与数字 Apple 系统字体、大字与共用对齐线；保留今天课表、任务分析、投入时长和剩余时间。小时刻度保持稳定，任务精确到分钟，实际计时可到秒。这些来自当前项目的 [设计意见记录](设计意见记录_2026-09-23.md)。

建议先设计 4 个可辨识的动作，并让基础组件共享它们的节奏：

1. **打开今天：**稳定框架中，课表和摘要轻轻就位，视线落到当前任务。
2. **把事情放进时间：**任务拖起后显示准确分钟落点，落位后还原成清晰时间块。
3. **进入专注：**所选任务与计时条建立明确关系，其余内容适度退后但不丢失。
4. **收好这一段：**结束专注显示真实时长，累计更新一次，随后恢复安静。

按压、分段选择、菜单、详情、完成与撤销围绕这四类动作使用一致的力度和速度。普通动作也可以有巧思；重点是相互配合，避免把不同产品最显眼的效果叠在同一个页面上。

更完整的 30 类状态、建议时长、入场时间线、失败恢复与验收方式见 [交互规格草案](留白_30类交互与页面入场_规格草案_2026-09-23.md)。数值均是待比较的起始方案，未获用户最终选定，也未在正式 App 实施。

## 六、怎么做出结果：设计与实现同时推进

**第一步，画状态，不只画页面。**每个组件先列默认、指向、按下、进行中、成功、失败、取消。写清内容何时可操作、谁获得焦点、旧状态如何恢复。

**第二步，做同内容的节奏对照。**同一套课表、标题和任务，制作偏干脆与偏柔和的两个运动版本，只改变速度、位移与弹性。用正常速度判断操作感，再慢放定位问题。这样才能知道差异来自哪里。

**第三步，把设计放进真实使用链。**进入今天 → 创建任务 → 安排 → 改时间 → 开详情 → 专注 → 完成 → 撤销。包含长标题、连续点击、空数据、慢请求和失败。漂亮的单个按钮不能代替整个过程通过。

**第四步，在目标设备上打磨。**桌面鼠标、键盘、触屏的操作方式分别设计；阅读、精确编辑、拖动都应顺畅。记录错误点击、找控件的时间、是否丢失上下文与重复操作后的疲劳。审美选择由对照体验辅助，不伪装成一个可自动算出的“高级感分数”。

Web 实现方面：[S26 · web.dev 动画性能指南](https://web.dev/articles/animations-guide)用于检查渲染成本；[S27 · MDN View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API)用于评估页面/元素状态过渡；[S28 · MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)用于按系统偏好提供静态或较少运动的对应表现。使用某个 API 不自动获得流畅度，需检测支持、设计回退并实际测量。
