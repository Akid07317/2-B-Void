# 开工顺序与交付边界

基线：SPEC_CN.md planner.v1.1；验收合同：ACCEPTANCE_CN.md。reference/ 仅供追溯，不覆盖新版规则。

## 第一阶段：可运行的领域核心

实现任务、工作块、保留时段、执行段、剩余量和计划快照；显式校验时间单位、状态和依赖。使用本地持久化，写入有事务、版本与幂等。先实现确定性贪心排程及独立输出校验，不以接入优化器为前提。

完成标准：通过适用的领域与贪心用例，真实创建任务、记录投入、计算计划、重启后恢复。协议 fixtures 使用实际函数输出，不冒充求解器证明。

## 第二阶段：个人可用的界面闭环

任务表单默认仅要求名称、任务类型、剩余分钟或探索预算；验收条件用一行文字即可，重要性和可拆性提供默认值。复杂字段收进高级设置。未知耗时允许存草稿。

界面包含任务列表、周日历、今天执行、待确认事项。结束工作时提供“完成”“按计划推进”“改剩余”“稍后确认”；可在关闭确认中填写简短证据。调整提案展示实际受影响时段，支持一次确认；不要求用户理解模型枚举。提供本地数据导出和恢复入口。

完成标准：端到端 E01 实际跑通，重启不丢数据，漏记与冲突可在界面解决，不靠改数据库。

## 第三阶段：改善安排质量

对真实小规模任务集比较手工、贪心和优化候选，记录生成耗时、未安排量与变更数。只有观察到贪心缺口时再接优化器；接入也必须使用相同协议、校验器和方案比较器。

暂不做：登录、多人协作、云同步、外部日历写入、复杂学习状态、自动知识图谱、强化学习、论文全量复现。
