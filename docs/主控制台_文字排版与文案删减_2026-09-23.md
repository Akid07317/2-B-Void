# 主控制台：文字排版与文案删减

> 后续意见更新：保留大字、思源宋体与共享对齐线；主日程改为课表式时间网格，时间统计显示到秒，并重新研究图标质感。下文旧原型的行列表和分钟统计示例不再作为最终目标，参见《高级质感_液态课表与秒级时间_调查_2026-09-23.md》。

2026-09-23。与《主控制台设计调查》合并作为下一版设计依据。本轮完成排版调查、文案审计与独立交互设计稿；未修改正式 App 或数据库。

## 1. 本轮设计决定

中文继续思源宋体，英文和数字使用 Apple 平台系统字体。正文默认 18px，辅助文字以 14px 为下限；提供 20px 的更大文字对照。通过共享列、行高和数字基线保持工整。主控制台仍包括今日概况、图标日程、当前专注、任务分析和投入分布。

用删除重复文字来腾出空间，保留直接影响判断的状态、口径、错误和后果说明。文字放大之后允许模块和行高随内容增长，不把文字强行塞回原来的小卡片。

## 2. 调查依据与适用边界

- Carbon 要求同一任务区域保持文字样式一致，标题与正文成套匹配行高；用稳定层级支持操作和阅读。本项目据此建立有限的字号角色，而不是逐组件随意定尺寸。[Carbon Typography](https://carbondesignsystem.com/elements/typography/style-strategies/)
- DWP 的提示文字规范建议先改清楚标签，只有明确需要时再添加简短提示；不可跳过的重要信息不应塞进容易被忽略的提示小字。这里借鉴其信息取舍原则，不照搬政府表单的视觉样式。[DWP Hint text](https://design-system.dwp.gov.uk/guidance/hint-text)
- W3C 中文排版需求讨论中西混排、标点和行内布局。这里保持中文自然行距，时间与单位成组，避免用连续空格、全角空格或逐字位移拼出假对齐。[中文排版需求](https://www.w3.org/International/clreq/)
- W3C 的文本缩放准则要求放大至 200% 不丢失内容或功能；文本间距准则要求用户增大行距等时依旧可读可操作。这是后续验收目标，不表示当前设计稿已经完成合规测试。[Resize Text](https://www.w3.org/WAI/WCAG21/Understanding/resize-text)、[Text Spacing](https://www.w3.org/WAI/WCAG21/Understanding/text-spacing)

Apple Typography 页面本轮正文抓取有限，搜索摘要可确认其强调字号层级与避免字体过度混用；不据此杜撰 Apple 指定的 Web 字号。下表全部是本项目的设计选择，不是平台规定。[Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography)

## 3. 字号与位置

|角色|默认字号 / 行高|位置与规则|
|---|---|---|
|页面标题|32 / 40px|主内容左上，“今天”只出现一次主标题，不再加英文副标题。|
|模块标题|22 / 31px|卡片左上，与正文共用左边缘；相邻卡片标题带同高。|
|任务名、当前任务|18 / 28px|左对齐，允许自然换行，禁止通过缩字适应长标题。|
|导航、按钮、统计标签|16 / 24px|导航固定文字起点；按钮围绕文案自适应，重复列表的动作列共享宽度。|
|日期、类别、次要状态|14–15 / 22–24px|任务名下方一行；只保留类别、时长、必要状态。|
|统计数字|36 / 49px|四格共用数值基线；同类时间统一为分钟，单位 14px。|
|专注计时|48 / 62px|固定数字格式，等宽数字，秒数改变不影响其他元素。|

更大文字对照以 20px 正文为基准，其他角色按比例放大。正式落地使用相对单位；不要因进入手机尺寸而把正文重新缩回 12–14px。

## 4. 文字怎样放才整齐

### 页面与卡片

页面标题、统计区域、日程模块共用主内容左边缘。统计每格内部固定为“标签 → 数值 → 一条必要说明”，三条水平线一致。所有指标左对齐；单位与数字对齐到文字基线，避免垂直居中造成单位上下漂移。

模块内部左右留白一致；标题距离正文固定。旁边模块内容多少可以不同，但不靠不同 padding 把标题视觉上凑齐。长内容可以自然长高，不用固定高度裁掉文字。

### 日程行

桌面共享“时间 / 图标 / 文字 / 动作”四列。时间右边缘、图标中心、任务名左边缘、完成按钮中心分别贯穿所有行。任务名与说明放在同一个文字列；第二行从任务名左边缘开始，不退到图标下面。

常规行只有任务名和一行元信息，例如“科研 · 45 分钟 · 下一项”。长任务名允许完整换行，时间、图标和动作仍对齐第一行，不随文字总高度上下居中。不要让“安排”“继续安排”“已安排”的不同长度挤动每一行的标题列。

窄屏减少并排列数，类别保留在元信息里。更大文字或长标题时增加行高，不隐藏重要状态，不依赖悬停才能读到名称。时间范围尽量保持同组，不从冒号中间折行。

### 中文、数字和图标

- 中文不人为拉大字距，不使用两端对齐把短标题撑满一行。
- 数字使用等宽数字特性；所有时间指标采用“75 分钟、105 分钟、45 分钟”，降低单位变化带来的视觉跳动。详情中可以显示小时与分钟。
- 正文中文、数字、单位共享自然基线；只在图标容器上统一视觉居中，不对每段文字加不同 top/translateY。
- 图标家族与尺寸一致，视觉尺寸不等于点击区域。图标配文字标签，手机导航图标保留可访问名称。
- 字重只设常规与强调两档；优先用字号和位置建立层级。只有本地 Regular 字体时，强调字重可能由浏览器合成，正式发布应校验实际字重资源。
- 重要信息使用高对比度正文色，辅助信息仍需清楚可读；不通过“灰到看不见”减少界面噪声。

## 5. 逐项文案处理

|现有文字|处理|改后位置 / 文案|
|---|---|---|
|TASKS / SCHEDULE / LIUBAI / PERSONAL WORKSPACE|删除首页装饰性重复文字|中文“今日日程”“今日分析”即可；品牌保留“留白”。|
|工作空间 / 日计划、个人工作空间|从主控制台删除重复路径和单人空间描述|页面标题“今天”，导航保留清楚的页面名。|
|页头与日历中的重复 GMT+8|移到设置|确有跨时区日程时再在相关时间旁显示。|
|拖入任务安排时间，也可以使用“安排”按钮|删除常驻教程|首次使用详细排程时提供一次帮助；实际入口叫“安排”。|
|添加任务，回车保存|缩短|按钮“添加任务”，输入框有“任务名称”标签；回车是快捷操作，不占常驻正文。|
|补充完成标准，让下一步更清晰|去掉所有普通任务中的重复提示|任务确实缺必要信息时显示“待补信息”，点开相应字段。|
|15 分钟网格；通常至少 30 分钟，完整收尾可为 15 分钟|从首页删除|安排表单先用选项约束；确实选择不合法时就地解释，并保留“安排规则”入口。|
|已安排 X 分钟 · 每日上限 Y 分钟 · 缓冲 Z%|拆分层级|首页显示“计划剩余”“可用余量”；容量和缓冲设置在详情。|
|已完成，可撤销。没有新增实际工时|缩短重复成功提示|“已完成”与明确撤销动作；“完成不增加工时”放在统计口径。|
|已保存在本机、页尾再次保存在本机、版本号|取消重复常驻|设置/关于显示存储与版本；保存中或失败时才在相关位置显示状态。|
|启发式安排 · 未证明最优 · 此预览5分钟内有效|去掉首页实现细节|预览保留实际变更；过期时显示“预览已过期，请重新生成”。局限放说明。|
|确认并应用这份计划|缩短|“应用计划”；涉及锁定、移动或删除的实质变更仍在按钮前明确列出。|
|含计时与补记|保留|“已记录投入”指标下；避免把所有记录误称自动计时专注。|
|待核实 / 待估计 / 今晚截止 / 冲突|保留|与对应任务放在一起，用可执行入口承接。|
|失败原因和操作后果|保留并写具体|例如“与 15:00 的概率论冲突”“完成将取消后续 2 个预约”。|

“删除”针对重复常驻说明，不删除真实约束或隐藏操作后果。相关提示应出现在做决定的位置，而不是提前铺满首页。

## 6. 主控制台合并设计

- 页头仅“今天 + 日期 + 添加任务”。
- 一行四项：今日进度、已记录投入、计划剩余、可用余量。
- 主区左侧：带时间、图标、名称、元信息和动作的日程；当前/下一项适度强调。
- 主区右侧：专注控制和今日分析。分析只写影响决定的两三行，例如“未安排任务超出余量 45 分钟”，下接“查看待安排任务”。
- 下方：投入分布，以同一比例尺横向条形表示实际分钟；字段少于三四项时直接标数值，不叠加图例或解释段落。
- “统计口径”默认折叠；不把重要的“含补记”等信息完全藏进去。

设计稿使用明确标记的示例数据：2/4 个今日目标完成，75 分钟已记录投入，105 分钟计划剩余，45 分钟可用余量。固定课程独立显示，不算入任务完成率。支持正常一天、超载和空白状态；可切换 18/20px 文字与文字对齐线。完成本次目标不会自动关闭跨天科研任务，也不会制造实际投入。
