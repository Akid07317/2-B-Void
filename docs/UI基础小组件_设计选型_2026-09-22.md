# 留白：基础小组件与设计体系选型

核验日期：2026-09-22。补充《UI动效与LiquidGlass_研究方案_2026-09-22》，这次关注按钮、表单、选择、反馈等基础组件。以下“代表性方案”指成熟设计系统和公开组件实践，不是市场占有率排名；对留白的取舍是项目建议。

## 设计体系与实现工具分开选择

| 参考对象 | 官方定位 / 可观察的做法 | 留白可借鉴的部分 |
|---|---|---|
| Apple HIG | 区分按钮内容与角色；系统组件承担平台交互约定 | 动作名称清晰、常用图标、主次关系；导航和短浮层选择性使用玻璃 |
| Material 3 Expressive | 以形状、颜色、大小、运动和分组强化关键操作；提供按钮组、分裂按钮等组件 | 专注入口、完成反馈、按钮组有少量表现力；密集任务行保持安静 |
| Fluent 2 | 明确区分 Field、Input、Combobox、Tag、Toast 等控件的职责 | 表单、复杂选择、就地反馈、桌面工具的行为细节 |
| Ant Design | 广泛覆盖输入、选择、日期时间、表格、树、抽屉和反馈 | 设置、课表规则和资料管理逐渐复杂后的组件能力；外观仍按留白统一 |
| shadcn/ui | 开放组件源码、可组合的接口与默认样式 | Web 组件的结构与定制方式；不把默认外观当作必须照搬的视觉体系 |
| Radix Primitives | 可定制、低层次、无预设样式的 React 行为组件 | 菜单、浮层、焦点与键盘操作；它是行为基础，不是一套视觉皮肤 |

官方依据：[Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)、[Material](https://m3.material.io/)、[Google Expressive 设计研究](https://design.google/library/expressive-material-design-google-research)、[Fluent 组件](https://fluent2.microsoft.design/components/web/react)、[Ant Design 组件](https://ant.design/components/overview/)、[shadcn/ui](https://ui.shadcn.com/docs)、[Radix](https://www.radix-ui.com/primitives/docs/overview/introduction)。

当前前端是原生 HTML/CSS/JavaScript。可以借鉴这些体系的设计和行为，不必仅为按钮皮肤迁移框架。若以后选择 React，再单独评估组件代码与运行依赖。WAI-ARIA APG 是交互模式参考，不替代具体组件的真实键盘、读屏和触屏测试。[W3C 模式目录](https://www.w3.org/WAI/ARIA/apg/patterns/)

## 24 类基础组件

表中的外观、动画和用途是给留白的建议。组件种类与常见行为参考上面的官方目录；参数不代表行业统一标准。

| # | 组件 | 建议的视觉与结构 | 微交互 / 动效 | 留白中的例子 |
|---|---|---|---|---|
| 01 | 普通按钮 | 主操作实心，次操作浅底/描边，低强调操作透明；同一区域层级清楚 | 悬停、按压、键盘焦点、等待和失败都有独立表现；提交时保留宽度 | 保存、新建、取消 |
| 02 | 图标按钮 | 图标尺寸统一，点击区域大于图形；陌生动作配文字 | 轻背景和按压反馈，补充说明可用 Tooltip | 上一天、搜索、更多 |
| 03 | 分裂按钮 Split button | 左侧执行默认动作，右侧箭头打开相关选项 | 两个区域分别反馈，菜单从箭头附近展开 | “开始 25 分钟 ▾”，菜单选择其他时长 |
| 04 | 按钮组 / 切换按钮 | 相关动作成组；可开关的按钮有持续选中状态 | 选中底片移动或填充变化；不让每个按钮独立跳动 | 显示已完成、锁定工具 |
| 05 | Switch 开关 | 轨道和滑块明确表示开/关，旁边保留名称 | 滑块短距离移动；异步失败恢复之前状态并解释 | 显示周末、开启提醒 |
| 06 | Checkbox 复选框 | 勾选区与文字共同可点击；批量选择需要半选态 | 勾与填充短过渡；完成动画不等于业务已提交 | 完成任务、多选导出项目 |
| 07 | Radio 单选组 | 少数互斥选项直接可见，当前项清楚 | 内点或选中区域短过渡 | 只修改本次 / 后续重复项 |
| 08 | Tabs / 分段控件 | Tabs 组织内容面板；分段选择适合一组短且互斥的模式 | 指示器连续移动，内容保持位置；允许快速反向切换 | 任务/记录面板；日/周视图 |
| 09 | 输入框 / 文本区 Field | 标签、输入区域、说明、错误构成一组；标签不依赖占位符 | 聚焦边界变化；错误就地出现；不每输一字重绘整行 | 任务名称、备注、课程名称 |
| 10 | 数字输入 / Stepper | 允许直接键入，配加减按钮和单位 | 数值稳定更新；边界禁用；不做长时间数字翻滚 | 预计 45 分钟、每天投入上限 |
| 11 | Slider 滑块 | 用于可连续调整或允许近似的值，显示当前数值 | 滑块始终跟手，释放后才允许短吸附 | 实验中的透明度；正式工时优先数字输入 |
| 12 | Select / Combobox | 简单选项用 Select；多选项检索用可搜索列表；输入过滤和已选值分开 | 列表展开、选中反馈；打字不反复播放整表进场 | 选择课程、项目、前置任务 |
| 13 | Chip / Tag 标签 | 显示型、筛选型、可移除型各有明确形态；不把所有标签都做成按钮 | 筛选时填充/勾选；移除时邻近项平滑收拢 | 数学竞赛、今天、45 分钟 |
| 14 | Badge / 状态点 / 计数 | 紧凑，文字清楚；状态色有固定语义 | 计数短更新；未读点通常静止 | 收集箱 3、草稿、待确认 |
| 15 | 日期 / 时间选择器 | 快捷值加可直接输入的精确值；完整日历按需展开 | 选中日期底片移动；面板稳定开合 | 今天、明天、本周；14:30 |
| 16 | Command palette 命令面板 | 搜索与常用动作集中，结果分组，快捷键可见 | 打开后输入框获得焦点，结果更新克制 | 查找任务、新建、跳到某日 |
| 17 | Menu / Context menu | 有动作名称、可选图标、快捷键；危险动作单独分组 | 从触发位置展开；键盘移动；关闭恢复焦点 | 复制、移动到明天、取消安排 |
| 18 | Tooltip / Popover | Tooltip 放简短补充说明；Popover 可容纳编辑与操作 | 小幅进入退出，避免遮住被解释的控件 | 图标说明；编辑时长的小浮层 |
| 19 | Toast / Snackbar | 短反馈，可带撤销；不遮挡输入与拖放目标 | 出入平滑，不抢焦点；可关闭 | 已移到明天 · 撤销 |
| 20 | 行内消息 / Banner | 与对应字段或区域相邻；重要错误持续可见 | 更新提示时保留布局稳定；不只靠闪红 | 与课程冲突、保存失败 |
| 21 | Progress / Spinner / Skeleton | 进度已知用数值，未知用等待标识；加载占位对应真实结构 | 平滑更新；减少动效时安静显示；快速请求避免闪烁 | 导入课表、保存中、加载任务 |
| 22 | Accordion / Disclosure / Tree | 折叠次要细节；树用于真实层级，避免制造无必要的嵌套 | 箭头旋转、内容展开；保持键盘与滚动位置 | 高级选项、课程与章节 |
| 23 | Avatar / 图标 / 快捷键提示 | 有实际身份或操作含义才出现；图标统一线条与尺寸 | 状态变化时短更新，不做无关循环动效 | 未来协作头像、⌘K 提示 |
| 24 | Separator / Splitter / 拖动手柄 | 分隔线表达分组，可拖分隔条表达可调整布局 | 手柄悬停/聚焦显现，拖动跟手 | 任务列表与日历列宽调整 |

## 几个容易混用的组件

### Switch 与 Checkbox

开关用于立即生效的二值设置；复选框可表达选择、任务完成或提交前的表单值，并支持半选状态。若还要按“保存”才应用，优先考虑复选框或明确说明设置应用方式。[Fluent Switch 使用说明](https://fluent2.microsoft.design/components/web/react/core/switch/usage)

### 标签与按钮

“数学竞赛”可以只是分类文本，也可以是筛选器或已选项。我们分别采用：静态标签不显示按钮反馈；筛选标签有选中状态；可移除标签有明确移除操作。Material 将 chips 分成不同用途，是这类设计的直接参考。[Material Web Chips](https://material-web.dev/components/chip/)

### Tooltip、Popover 与 Menu

Tooltip 只补充简短说明，不承载必须点击的功能；Popover 可用于小型表单或详情；Menu 用于一组命令。它们可能外观接近，但焦点、键盘和关闭逻辑不能混用。[W3C 模式目录](https://www.w3.org/WAI/ARIA/apg/patterns/)、[Radix 组件能力](https://www.radix-ui.com/primitives)

### Select 与 Combobox

Select 用于从既定选项选值；需要输入过滤、自动补全或处理较多候选时，再采用 Combobox。自制时应明确输入焦点、方向键选择、Enter 接受、Escape 关闭等行为。[W3C Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)

### Toast 与错误信息

“已保存”“已移动，可撤销”适合短反馈。影响继续操作的错误，如时间冲突、保存失败，需要在相关位置留下可查看的说明，不能只在数秒后消失。

## 视觉方向怎么选

可将参考方案按产品观感理解为三条路径。这个分类是本项目的设计归纳，不是各厂商的官方分类。

1. **清晰、克制的工具界面**：少量强调色，稳定的文字与行高，浅填充和细边界，小范围动效。适合留白每天反复录入、查看和安排任务的主体。
2. **更有表现力的交互**：更明显的形状变化、分组、色彩与弹簧。适合专注入口或少量完成反馈。Material 3 Expressive 是可深入研究的参考。
3. **有材质与空间层次的控件**：透明、厚度、高光、来源明确的展开。适合浮动工具栏、导航、菜单与计时浮条。Apple Liquid Glass 是参考。

玻璃、拟物、发光描边等单一视觉效果不能直接决定控件用途。选型先看用户要输入、选择、执行、查看还是获得反馈，再决定材质与运动。

## 给留白的具体组合

- 主体：统一的小圆角或圆角矩形、克制强调色和稳定任务行；主操作与次操作有明确区分。
- 标签：分类与状态分开；同一课程颜色保持一致；不要每种信息都用高饱和胶囊。
- 输入：任务名称就地输入；时长用数字输入和快捷值；选择课程用搜索列表。
- 反馈：完成勾选、已保存、可撤销都有就地反馈；等待过程不显示虚构百分比。
- 材质：玻璃留给日期工具栏、短菜单、手机导航与专注浮条；普通输入框、复选框、状态徽标共享统一基础风格。
- 动效：只给组件的状态变化做短过渡；拖动和滑块跟手；日常操作不等待动画播放完。

先定义一套组件状态表，再选外观。适用状态包括默认、悬停、键盘焦点、按下、选中/勾选、禁用、等待、成功、错误；不是每个组件都需要全部状态。触屏没有悬停，因此关键动作必须随时可访问。

建议第一批落地 12 类：按钮、图标按钮、复选框、开关、分段选择、输入框、数字时长输入、课程搜索选择、分类标签、短菜单、行内错误与撤销提示。它们能覆盖当前日计划的大部分日常操作。

本轮只补充组件选型文档，没有安装组件库或修改正式界面。
